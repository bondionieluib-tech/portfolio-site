Overview

Why I built it.

ClimaCore is not a real company. I made it so I could build and test the pieces a small service business actually needs, in one place, instead of in separate disconnected demos: a public website, a branded support inbox, a way for customers to book, reschedule and cancel, and an assistant that can answer common questions.

Each piece below is labeled with where it stands today, and I update the labels as the build moves forward.

What's In It

Six parts, one business.

Landing page

Live

A marketing site for the company, hosted on Vercel under its own subdomain.

Support email routing

Live

A branded support address on a custom domain, set up with Cloudflare Email Routing and forwarded into a working inbox.

Booking workflow

In progress

A new booking comes in through a webhook, gets matched against existing customers in Airtable, creates or updates the record, sends a Gmail confirmation, and logs the change to a Postgres audit table. A day-before reminder is part of the same build.

Rescheduling workflow

In progress

A reschedule request is looked up in Airtable, confirmed by email, and sent to a technician for approval through Telegram, with a calendar-based availability check being added.

Cancellation workflow

Planned

The third leg of the booking system. It will follow the same pattern as the other two.

AI chat agent

Planned

A website chat widget backed by a retrieval pipeline over the company's own FAQs and service info, with an offline notice when the backend isn't running.

Under the Hood

How a booking flows.

The booking workflow as it currently stands.

New booking
Webhook→ Search Airtable→ Existing customer?→ Update or create record→ Gmail confirmation→ Postgres audit log
Reschedule
Reschedule form→ Search Airtable→ Gmail→ Technician approval (Telegram)→ Confirm or reassign
About this project: ClimaCore is a demonstration, built to show how I design and connect these systems. The workflows run on my own self-hosted n8n, so the live chat agent will show an offline notice whenever that server is down; the rest of this site doesn't depend on it.
